## Service Overview
The Cloud Viability Assessment (CVA) is Ingram Micro's structured assessment designed to provide customers with a clear, evidence-based view of their current infrastructure estate and its readiness, suitability, and commercial viability for migration to AWS. The CVA combines technical discovery, cost modelling, and business-aligned analysis to help customers understand the implications, benefits, and investment profile associated with a transition to AWS.
Leveraging live systems and utilisation data, the full version of the CVA produces a detailed and accurate representation of the customer's server estate, including Windows, Linux, and SQL workloads, utilisation patterns, and storage consumption. This dataset becomes the foundation for a series of analyses aligned to the AWS Optimisation and Licensing Assessment (OLA) framework, enabling AWS funding, precise rightsizing, instance family selection, licensing considerations, and deployment blueprinting.
The assessment also incorporates AWS-aligned pricing and optimisation methodology. Through comparative scenario modelling (including 1-Year/3-Year Reserved Instances, and Savings Plans) the CVA demonstrates how architecture and commercial decisions impact cloud cost over both short-term and multi-year horizons. Where relevant, the CVA also assesses cross-cloud commercial differences (for example, Azure to AWS migration scenarios), highlighting potential efficiency and cost savings.
The result is a concise, decision-ready assessment that gives stakeholders a clear understanding of:
The current infrastructure landscape and utilisation characteristics.
The recommended AWS instance blueprint that best fits observed requirements.
The cost and licensing implications of moving to AWS under multiple commercial models.
The 1-year and 5-year financial impacts compared to current state or alternative clouds.
The high-level customer-specific AWS architecture and migration approach required to support transition.
The key next steps needed to progress into AWS migration planning (MAP Assess/Mobilise).
The scope of the Full CVA is as follows:
### Cloud Viability Assessment (Full)
Stage Description: The Full CVA, delivered in conjunction with AWS Optimisation and Licensing Assessment (OLA) practices, is structured into clear delivery phases. Each phase provides defined outputs that build toward a comprehensive understanding of the customer's estate, AWS target sizing, and financial modelling.
Phase 1: Tool Deployment, Configuration and Validation. Ingram Micro installs, configures, and validates the selected data collection tool (for example AWS Migration Evaluator or a third-party collector). This includes agent deployment (where required), connection to hypervisors or cloud APIs, configuration of metric capture, and validation of data ingestion. Deliverables:
Tool deployment and configuration summary
Data collection readiness validation
Observation period plan and data coverage confirmation
Phase 2: Observation Period (Live Data Capture). The collector gathers utilisation metrics over the agreed period (typically 14 to 30 days), capturing real CPU, RAM, storage IOPS, network, and runtime behaviour. Deliverables:
Weekly data-collection health checks
Interim coverage and completeness reports
Phase 3: Infrastructure Inventory and Workload Profiling. The captured dataset is analysed to build a detailed and accurate representation of the customer's estate across multiple dimensions. Deliverables:
Full server inventory
Licensing footprint (Windows, SQL, Oracle depending on tool)
Workload utilisation heat maps
Phase 4: AWS Rightsizing and Instance Blueprinting. Using real utilisation metrics, workloads are matched to optimal AWS instance families/sizes, storage types, and tenancy models. Deliverables:
Utilisation-based AWS rightsizing outputs
Instance blueprint including family, type, count, tenancy, and region
Phase 5: Licensing Optimisation and Scenario Modelling. The assessment correlates licensing entitlements with workload behaviour to identify BYOL options, consolidation savings, SQL/Windows optimisation paths, and dedicated host placement considerations. Deliverables:
Licensing optimisation report
BYOL vs. License Included modelling
SQL licensing scenario outputs
Phase 6: AWS Cost Modelling and Multi-Scenario Analysis. AWS 1-year/3-year Reserved Instance and Savings Plans scenarios are modelled, including comparisons against current-state costs (on-premises/other cloud). Deliverables:
Reserved Instance and Savings Plan modelling
Multi-year (1-year and 5-year) financial forecasts
Phase 7: High-level Architecture and Migration Strategy. A high-level architectural review is conducted for the recommended AWS target environment, covering account structure, landing zone design, network segmentation, and alignment with AWS migration best practices such as the 6Rs and MAP frameworks. Deliverables:
Conduct a customer workshop to gather detailed information on applications, business criticality, key objectives, challenges, and infrastructure sizing.
Define the high-level architectural strategy aligned with business and technical requirements.
Develop high-level migration strategy indicators using the 6Rs framework.
Define the application and infrastructure modernization strategy.
Identify the appropriate MAP funding motion based on the migration approach.
Articulate AWS Cloud benefits and map them to existing challenges to demonstrate how they will be addressed and mitigated.
Phase 8: Executive Report and Stakeholder Presentation. All findings are consolidated into a decision-ready assessment and formal readout. Deliverables:
CVA assessment report including cost analysis, customer-specific architecture strategy, AWS cloud benefits, MAP funding motions
Stakeholder presentation and readout session
### Deliverable(s)
The Full CVA produces a decision-ready technical, commercial, and architectural assessment that establishes the baseline and foundational direction for the customer's AWS migration planning and overarching cloud transformation journey. This assessment is delivered through a set of clear, actionable outputs designed to support confident decision-making and next-step planning, including:
A comprehensive written assessment report summarising key findings, AWS sizing, cost modelling, and recommendations.
A stakeholder presentation / executive readout providing a clear narrative of insights, financial outcomes, and next-step options.
A right-sized AWS instance and cost baseline offering the technical and commercial blueprint for migration planning.
### Exclusion(s)
The Full CVA focuses solely on assessment and analysis activities. The following high-level areas are explicitly out of scope for this engagement:
Implementation, configuration, or modification of AWS services (no build, deployment, or hands-on engineering).
Remediation or optimisation of existing workloads (no tuning, patching, or changes to on-premises or cloud systems).
Migration delivery or modernisation activities (no workload moves, refactoring, re-platforming, or PoCs).
Detailed solution design or low-level architectural documentation (LLDs, runbooks, IaC, etc.).
Licensing procurement or license entitlement validation.
Ongoing managed services, monitoring, support, or cost-optimisation beyond the assessment output.
### Caveats and Assumptions
The Full CVA is delivered based on the following key assumptions:
The Partner will ensure the End-Customer grants the necessary access and permissions to all relevant systems, allowing Ingram Micro to install, configure, and operate the agreed data-collection tooling for the capture of system and utilisation metrics.
The provided access reflects a representative and current view of the in-scope estate, driving the collection of relevant metrics (for example utilisation, OS details, storage allocations, and workload classifications).
The Partner and End-Customer will make the appropriate stakeholders available for installation, configuration, discovery, clarification, and review sessions.
All analysis is non-intrusive and conducted exclusively on performance, utilisation, and configuration data collected by the installed assessment tooling. While the tooling requires controlled access to the environment to enable data capture, it does not collect, transmit, or process any personally identifiable information (PII).
All pricing and cost models are indicative, based on AWS public pricing for the agreed region and currency at the time of assessment.
Licensing information supplied by the Partner or End-Customer is assumed to be accurate, with no entitlement validation or compliance checks performed.
Any cross-cloud comparisons (for example Azure to AWS) assume the Partner or End-Customer provides accurate cost data for comparison.
The engagement is advisory only, with no implementation, migration, remediation, or configuration work included.
Timelines are dependent on the timely provision of access and stakeholder availability.
The Partner will ensure the End-Customer is aware of, and fulfils, their obligation to provide formal completion sign-off following delivery of the Full CVA.
The Partner will cover the associated AWS Funding Value for the Full CVA and will provide a valid Purchase Order (PO) to Ingram Micro upon request if End-Customer sign-off is not received before the expiration of any applicable vendor funding.

For this engagement, the following engagement governance will be included: Technical Consultant and Project Coordinator.
### Technical Consultant
The Ingram Micro Technical Consultant supports partners and end-customers throughout AWS OLA engagements by providing technical guidance during the data collection and assessment phases. They act as a key technical contact for partners, ensuring smooth coordination and alignment with AWS processes and best practices.
The consultant supports infrastructure data collection and validation while ensuring required datasets are ready for assessment activities. They prepare engagement deliverables and engage with partners during technical discussions.
At a high-level the core responsibilities for the Technical Consultant include:
Verify customer eligibility (ARR of at least $50K) and create the ACE opportunity and corresponding funding request in the AWS portal.
Conduct the workshop to capture existing challenges, objectives, application landscape details and expectations.
During the kick-off call, confirm the preferred data collection method (ME Tool or 3rd Party Tool).
Review the deployment of the AWS Migration Evaluator collector and assist with troubleshooting installation, connectivity, or data collection issues if the Partner requires support.
Validate the collected VM inventory and performance metrics (CPU, memory, storage, utilization) and upload the dataset to AWS TSO Logic for analysis.
Perform workload rightsizing and map on-prem workloads to appropriate Amazon EC2 instance families and Amazon Elastic Block Store storage.
Create the high-level architecture and migration strategy based on customer requirements.
Generate the CVA report and conduct a technical playback session with the Partner to review sizing assumptions, optimization opportunities, and migration insights.
### Project Coordinator
The Project Coordinator helps ensure smooth execution of engagement tasks by managing schedules, maintaining documentation, and tracking actions and updates. They coordinate meetings, prepare agendas, and record meeting minutes to support effective communication. The role also involves monitoring day-to-day tasks and collecting status updates from the team. Additionally, the Project Coordinator assists with reporting, resource updates, and document control throughout the engagement lifecycle.
At a high-level, the core responsibilities for the Project Coordinator include:
Support the engagement with administrative and coordination tasks.
Maintain engagement documentation, RAID updates, and action logs.
Schedule meetings, prepare agendas, and record minutes.
Track day-to-day tasks and collect status updates.
Assist with reporting, resource updates, and document control.
